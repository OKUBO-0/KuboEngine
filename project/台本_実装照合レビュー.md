修正文:

> レベルアップ候補は `LevelUpChoiceService` が `PlayerManager` の状態から生成します。武器候補には弓矢、岩石、雷の杖、炎の杖、ソードなどがあり、取得済みか最大レベルかを確認してから候補へ加えています。候補の適用処理は `PlayerManager` 経由で `PlayerWeaponController` に集約し、武器ごとの更新・強化処理をシーン本体から切り離しました。

### 2. 検証結果の数値を1つの根拠に統一する

台本の「Debug/Release x64、CPUテスト、シーン遷移3周、SRV 105/105」は `README.md` の 2026-06-19 時点の確認済み状態と一致します。

### 3. Shadow Mapの「未計測」表現を更新する

台本では「GPU時間としてどの程度の負荷になっているかは未計測」とありますが、現在の `generated/outputs/scene_transition_stress.txt` には Shadow GPU 時間が記録されています。

ただし、これはストレス実行中の記録であり、Shadow Pass有効/無効やcaster数をそろえた比較ではありません。したがって「完全に未計測」ではなく「比較計測は未実施」と書くのが正確です。

修正文:

> Shadow PassのGPU時間はシーン遷移ストレスログに記録していますが、Shadow有効/無効、caster数、Draw Call数をそろえた比較計測はまだ行っていません。現段階では、Shadow Mapの描画経路と状態遷移を実装し、候補数・提出数・GPU時間を記録できる状態までを成果として扱います。

## 実装と合っている主張

### エンジン層とゲーム層の分離

この主張はそのまま使えます。`engine/` と `game/directxgame/` の分離、`main.cpp` で `GameSceneFactory` を注入している構成、`GameSceneFactory.cpp` が `TitleScene`、`PlayScene`、`ResultScene` を生成する流れは実装と一致しています。

より自然な修正文:

> 共通機能は `engine/`、作品固有の処理は `game/directxgame/` に分けました。`main.cpp` では `GameSceneFactory` を `Game` へ渡すだけにして、具体的なシーン生成はゲーム側へ寄せています。この形にした理由は、別のゲームを作るときに、描画・入力・音声などの共通基盤へ作品固有のシーン名やルールを混ぜたくなかったためです。

### `PlayScene` を構成地点にする説明

`PlayScene.h` は `PlayerManager`、`EnemyManager`、`GameplayFlowController`、HUD、演出、デバッグ文脈を保持しており、台本の説明と合っています。

表現の調整:

> `PlayScene` はゲームプレイ全体を直接処理する場所ではなく、各機能を接続する構成地点として使っています。進行状態は `GameplayFlowController`、プレイヤーの能力や武器は `PlayerManager` と `PlayerWeaponController`、敵の生成・衝突・EXPは `EnemyManager` へ分け、シーン本体には更新順序と画面遷移の判断を残しました。

### `GameSession` の説明

`GameSession.h` と `GameSession.cpp` には、`RunResult`、コイン、恒久強化、キャラクター解放、選択キャラクター、ストレステスト記録があり、台本の方向性は合っています。

ただし「経験値をResultで集計」は、実装上は `RunResult` に `totalExp` と `coins` が保存され、Resultで表示されるという言い方の方が正確です。

修正文:

> シーンをまたぐ値は `GameSession` に集約しています。Play中に得た経験値、コイン、最終レベル、撃破数、経過フレームは `RunResult` として保存し、Resultシーンで表示します。さらに獲得コインはプロフィール側の所持コインへ反映し、Titleシーンで恒久強化やキャラクター解放に使います。

## 追加すると説得力が上がる内容

### 1. キャラクターごとの能力差

`characterStats.csv` と `GameSession` の `CharacterId` から、Octopus/Flame/Blade/Storm のキャラクター選択と解放があります。台本には少し出ていますが、資料では「恒久強化とキャラクター解放」だけでなく、選択キャラクターが `PlayScene` で読み込まれる点まで書くと実装のつながりが見えます。

追記案:

> キャラクターごとの初期能力は `characterStats.csv` に分け、`PlayScene` の初期化時に `GameSession` の選択キャラクターIDから読み込みます。これにより、Titleでの解放・選択と、Play中の能力反映を `GameSession` を介して接続しています。

### 2. GPU時間の記録機能

`DirectXCommon` には `BeginShadowGpuTiming`、`EndShadowGpuTiming`、P95/Max/Average取得があり、`GameSession` に記録されます。これは技術資料として強いです。ただし比較実験ではないため、性能改善の断言には使わない方がよいです。

追記案:

> `DirectXCommon` にはフレーム全体とShadow PassのGPU時間を記録する処理を入れています。現状はP95や最大値をログへ残せる段階で、最適化効果の比較には、同一条件での有効/無効比較を追加する必要があります。

### 3. CPU回帰テストの範囲

台本の検証説明は良いですが、`tools/cpu_regression_checks.cpp` を見ると、現在は次の範囲も確認しています。

- 空間セルキー
- 候補削減率
- HP/ゲージのクランプ
- CSVの厳密解析
- 武器攻撃間隔
- プレイヤーステータス解決
- Run Seed
- `SoundHandle` の型契約

台本に「プレイヤーステータス解決」も入れると、成長・恒久強化・キャラクター差分の説明とつながります。
